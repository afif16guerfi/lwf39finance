# النظام المالي — الرابطة الولائية لكرة القدم الوادي (مشروع مستقل)

هذا مشروع مستقل بالكامل تم **فصله** عن مشروع "منصة انخراط الحكام"
(`lwf-eloued-referee-platform`)، الذي كان يستضيف النظام المالي سابقًا على
المسار `/finance` داخل نفس الخادم. الآن لكل منهما خادمه الخاص، وواجهته
الخاصة، ونشره الخاص — لكنهما **يتشاركان عمدًا نفس قاعدة بيانات MongoDB**
(نفس `MONGODB_URI`)، لذلك:

- كل حسابات "مدير النظام" (admin) و"المسؤول المالي" (finance_admin)
  و"مستخدم للعرض" (finance_viewer) الموجودة مسبقًا تعمل هنا مباشرة بنفس
  اسم المستخدم وكلمة السر، دون أي إنشاء جديد.
- كل العمليات المالية، جهات الصرف، السنوات المالية، وسجل التدقيق المسجَّلة
  سابقًا تبقى كما هي بالضبط.
- **لا حاجة لأي ترحيل يدوي للبيانات** — فقط شغّل هذا المشروع بنفس رابط
  قاعدة البيانات المستخدَم في مشروع منصة الحكام.

## ماذا يحتوي هذا المشروع

نفس وحدة "المالية" كما كانت بالضبط (نفس الواجهة، نفس الصلاحيات الثلاث،
نفس تصدير Excel/PDF)، بالإضافة إلى الحد الأدنى الضروري من الملفات المشتركة
لتشغيله كخادم مستقل تمامًا:

```
server.js                  خادم Express مستقل (منفذ افتراضي 4001)
routes/auth.js             تسجيل الدخول / me / تغيير كلمة السر (نسخة مصغّرة —
                            لا تسجيل حسابات حكام هنا، ذلك يبقى في منصة الحكام)
routes/finance.js          كل مسارات الـAPI المالية (كما كانت تمامًا)
financeCore.js             حساب الرصيد، الترقيم، التحقق من صحة العمليات
financeAuditCore.js        سجل تدقيق مستقل خاص بالوحدة المالية
financeExcel.js            بناء ملف Excel الرسمي (ExcelJS)
financePdf.js              بناء محتوى تقرير الـPDF الرسمي (HTML)
pdfRenderer.js             محرك HTML → PDF (Chromium عبر Puppeteer)
arabicShape.js             محفوظ للرجوع إليه فقط (غير مُستخدَم فعليًا — كما كان في المشروع الأصلي)
db.js                      طبقة قاعدة البيانات (نفس المجموعة/الوثيقة المشتركة مع منصة الحكام)
schema.js, settingsCore.js, documentRequirementsCore.js, auditCore.js
                            ملفات مشتركة يحتاجها db.js لضمان توافق شكل البيانات تمامًا مع منصة الحكام
middleware/auth.js         نفس منطق التحقق من الجلسة والصلاحيات
cloudinary.js              لرفع شعار الرابطة من إعدادات النظام المالي
public/finance.html/.js/.css   نفس الواجهة الأمامية بالضبط
public/styles.css          نظام التصميم المشترك (متغيرات الألوان/الخطوط) الذي تعتمد عليه finance.css
public/assets/logo.png     شعار الرابطة (نفس الملف)
assets/fonts/*.ttf         خط Tajawal المُضمَّن داخل ملفات PDF
```

## التثبيت والتشغيل محليًا

```bash
npm install
cp .env.example .env
# عدّل .env: ضع نفس MONGODB_URI المستخدَم في مشروع منصة الحكام
npm start
```

سيعمل الخادم افتراضيًا على `http://localhost:4001` (منفذ مختلف عن منصة
الحكام عمدًا، حتى يمكن تشغيل المشروعين معًا على نفس الجهاز أثناء التطوير).

> `puppeteer` يُنزّل نسخة Chromium خاصة به تلقائيًا أثناء `npm install`
> (بضع مئات من الميغابايت) — هذا طبيعي ومطلوب، فهو المحرك الذي يُنتج ملفات
> الـPDF.

## متغيرات البيئة (`.env`)

| المتغير | الوصف |
|---|---|
| `PORT` | منفذ الخادم (افتراضي 4001) |
| `JWT_SECRET` | سرّ توقيع الجلسات — لا يلزم أن يطابق سرّ منصة الحكام (كل مشروع يتحقق فقط من التوكنات التي وقّعها هو بنفسه، لأن تسجيل الدخول أصبح منفصلاً في كل مشروع) |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | تُستخدَم فقط إن كانت قاعدة البيانات فارغة تمامًا عند أول تشغيل (نادر الحدوث في الفصل، لأن الحساب عادة تم إنشاؤه من قبل منصة الحكام) |
| `MONGODB_URI` | **يجب أن يكون مطابقًا تمامًا** لرابط منصة الحكام — هذا هو ما يجعل البيانات موحّدة بين المشروعين |
| `CLOUDINARY_*` | لرفع شعار الرابطة (اختياري — نفس حساب Cloudinary المستخدَم في منصة الحكام إن أردت) |

## النشر كخدمة منفصلة (مثال Render)

نفس خطوات نشر مشروع منصة الحكام بالضبط، لكن كخدمة ويب **ثانية ومنفصلة**:

1. أنشئ خدمة Web Service جديدة على Render (أو أي مستضيف Node.js) من هذا
   المجلد/المستودع.
2. اضبط متغيرات البيئة أعلاه — **الأهم: `MONGODB_URI` مطابق حرفيًا لمشروع
   منصة الحكام.**
3. أمر البناء: `npm install` — أمر التشغيل: `npm start`.
4. بعد نجاح النشر، احصل على رابط هذه الخدمة (مثلاً
   `https://lwf-finance.onrender.com`) وضعه في ثابت `FINANCE_SYSTEM_URL`
   داخل `public/app.js` في مشروع منصة الحكام، حتى يعمل زر "💰 النظام
   المالي" في شريط الإدارة هناك.

> **ملاحظة Render لتنزيل Chromium:** إن ظهر خطأ "Could not find Chrome"
> بعد النشر رغم نجاح `npm install`، أعد النشر مع **تفريغ ذاكرة البناء
> المؤقتة بالكامل** ("Clear build cache & deploy")، لنفس السبب الموثّق
> في `pdfRenderer.js` وسكربت `postinstall` في `package.json`. يمكن التحقق
> من حالة محرك الـPDF عبر `GET /api/finance/export/pdf/diagnostics`
> (بحساب مدير).

## تسجيل الدخول بعد الفصل

سجّل الدخول هنا بنفس حساب "مدير النظام" أو "المسؤول المالي"/"مستخدم للعرض"
الذي كنت تستخدمه سابقًا على `/finance` — لا حاجة لإنشاء أي حساب جديد.

**الفرق الوحيد عن السابق:** لم يعد الدخول تلقائيًا بعد تسجيل الدخول في
منصة الحكام (كان ذلك يعمل سابقًا فقط لأن الصفحتين كانتا على نفس الخادم/نفس
أصل المتصفح). الآن، بما أن هذا المشروع على رابط مستقل، يجب تسجيل الدخول
هنا بشكل منفصل — بنفس اسم المستخدم وكلمة السر بالضبط.

## الصلاحيات (كما كانت تمامًا)

| الدور | إضافة عمليات | تعديل عمليات | حذف عمليات | التقارير/التصدير | إدارة جهات الصرف/السنوات المالية/المستخدمين/الإعدادات |
|---|---|---|---|---|---|
| مدير النظام (admin) | ✓ | ✓ | ✓ | ✓ | ✓ |
| المسؤول المالي (finance_admin) | ✓ | ✓ | ✕ | ✓ | ✕ |
| مستخدم للعرض (finance_viewer) | ✕ | ✕ | ✕ | ✓ (عرض فقط) | ✕ |

كل هذه الصلاحيات مُطبَّقة على الخادم (`routes/finance.js`) وليس فقط في
الواجهة — استدعاء الـAPI مباشرة بحساب غير مخوَّل يُرفض بخطأ 403.
